# V1.9.0 发布说明

## 新增与修复

- 存储位置扩展为 A、B、C1、C2、G1、G2；旧酸柜 `C` 数据自动迁移到 `C1`，酸碱柜明确提示只能存放已经人工确认的对应物质。
- 药品和代入库申请新增可选 CAS 号，支持格式与校验位验证、规范化传递、库存搜索和非唯一索引；既有记录保持为空，无需补录。
- 活跃药品归属人和超级管理员可更正名称、规格、CAS 号及入库时间；严格校验权限、状态与版本，并拒绝无实际变化的请求。
- 更正、字段级 before/after 审计处于同一事务；公开 HTTP/实时日志只返回可读摘要，结构化明细仅保存在服务端数据库。
- 更正界面使用可访问的应用内弹窗，保留当前库存视图和搜索条件，不使用浏览器原生 `prompt`/`confirm`。

## 数据升级

- 支持 fresh、V1.4 A/B-only 和 V1.5–V1.8 A/B/C SQLite 数据库直接升级。
- `chemicals`、所有状态的 `inbound_requests` 以及 `inventory_movements` 的历史来源/目标位置都会把 `C` 改为 `C1`。
- 迁移保留业务行、主外键、状态、版本、时间和既有索引；失败会完整回滚并恢复外键检查，多次重开保持幂等。
- 部署前必须停止旧服务并备份整个 `data/`。合成数据库迁移验证不代表远程真实数据库已经验证。

## 验证边界

- 本版本包含生产实现者保存的逐切片 RED/GREEN 证据，以及自动测试、类型检查、生产构建、acceptance 和本机性能回归。
- 本次工作没有执行或声称独立 DSH 审查；旧版本审查结论不外推到 V1.9.0。
